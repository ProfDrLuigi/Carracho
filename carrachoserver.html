New in 1.0.8

  • Updated Carracho Server for macOS to version 1.0.8 (build 9).
  • Added modern message editing on both the Swift/macOS and native Linux server runtimes. The server assigns and forwards edit metadata for Conference and Private Messages and enforces the five-minute edit window using server-side timing.
  • Message edits are restricted to the original sender and to text-only modern messages. Media-bearing messages are not editable, and edit events are never sent to Classic/Legacy clients, preserving the historical packet layouts.
  • Added persistent Bot File Watchers on macOS and native Linux. Watchers monitor configured folders recursively below the normal Files root, can use . for the Files root itself, detect newly created files and folders, coalesce bursts of changes, and rate-limit repeated announcements.
  • File Watcher announcement templates support {folder} for a clickable Carracho Files link and {file} for the detected file or folder name. Watcher paths are validated to remain inside the Files root.
  • Added remote Bot File Watcher administration through the Carracho client protocol and the HTTP Administration API, including persistent configuration, target-Conference validation, hot configuration reloads, and support for up to 32 watchers. The native Linux implementation uses inotify for filesystem events.
  • Removed the duplicate Automatic Greeting editor from the macOS Server window. Bot greetings remain fully supported and are configured centrally from the Carracho client's Administration interface.

New in 1.0.7

  • Updated Carracho Server to version 1.0.7 (build 8).
  • Closing the main macOS Server window with the red close button now quits Carracho Server completely, even when the menu bar icon is enabled. The separate “Hide Server Window” command still hides the window without stopping the server.

New in 1.0.6

  • Improved interoperability with original Carracho Trackers. Modern servers now register using the historical UDP CTT transport, while tracker queries continue to use TCP, and modern trackers emit the Classic list-record layout expected by original clients and servers.
  • Improved Tracker administration persistence on the native Linux server. Remote changes now preserve the complete Tracker list, including secondary trackers, and a missing carracho-server.json mirror can be recreated from the active server state.
  • Improved Classic banner compatibility. Legacy sessions receive a compact 350x45 version of the built-in Carracho banner while modern clients continue to receive the full-resolution artwork.
  • Added server-side media scoping for modern Private Messages. Image attachments are bound to the sender and recipient accounts, persist across reconnects, and cannot be fetched by unrelated accounts.
  • Kept Classic Private Messages isolated from modern media syntax: image messages are not delivered to Classic clients, normal text continues to use the historical MacRoman path, and token-like Classic text remains literal text.

New in 1.0.5

  • Upgraded the persistent file-search index to schema version 3 with two-character terms in addition to trigrams, making short searches such as 7z use the SQLite index instead of falling back to a full entries-table scan.
  • Existing version-2 search databases are migrated in place by backfilling the new two-character terms, avoiding an unnecessary full filesystem rescan.
  • Improved indexed search planning on the native Linux server so SQLite starts from matching term postings and only evaluates candidate entries instead of scanning the complete path-ordered file table.
  • Modern authenticated file-search transfers can now batch up to 256 results per frame, greatly reducing socket and AEAD framing overhead for very large result sets while preserving the historical one-result framing used by Classic clients.
  • Added a native Search Index status protocol that reports whether an index is ready or rebuilding and, when available, how many searchable entries it contains. The macOS and Linux servers expose the same status to the administration client.
  • Added GET /api/v1/log?limit=200 to the HTTP Administration API so WebAdmin can read recent persistent server-log entries even when Server-Sent Events are unavailable.
  • Improved native Linux configuration persistence. Bot and server settings now fall back to rewriting an existing configuration file when an atomic rename is not permitted by the deployment directory, preventing otherwise valid administration changes from failing.
  • Improved Linux deployment ownership handling by resolving the actual carracho.service runtime account and ensuring live server and Bot configuration files remain writable by the running service.
  • Administrators can now disconnect the local Server Bot through the normal user-disconnect path; the Bot is disabled cleanly instead of returning the generic server error previously seen by administration clients.
  • User Info replies now carry an explicit Legacy-transport marker on both macOS and Linux, allowing modern clients to identify Classic sessions reliably even when operating-system, CPU, and client-version metadata are absent.

New in 1.0.4

  • Added a bundled Web Administration interface for Carracho Server on macOS and native Linux, providing browser-based status, user, account, Conference, settings, search-index, broadcast, activity, and transfer administration.
  • Added an authenticated HTTP Administration API with Bearer-token protection. The API includes server status, users, accounts, Conferences, settings, broadcasts, search-index control, active transfers, and transfer cancellation.
  • Added live transfer monitoring to the administration API and WebAdmin, including direction, user, file path, progress, transfer rate, ETA, state, and remote cancellation.
  • The Linux WebAdmin is bundled as a self-contained helper and is started and stopped by the normal carracho-server process, so only one carracho.service is required.
  • Fixed a Classic download protocol mismatch that could crash the original client. Legacy downloads now consume both data-fork and resource-fork resume offsets and return both fork lengths before sending file data.
  • Added full historical Classic user-icon handling. Native 636-byte Classic icons are accepted during login and user updates, persisted with the account, and forwarded unchanged to compatible Classic clients.
  • Improved modern/Classic avatar interoperability so modern servers preserve real Classic icons instead of discarding them as invalid PNG data.
  • Expanded Conference administration with Operator Mode and Speak Permission updates, modern room deletion, and reliable deletion notifications while preserving the ordering expected by Classic clients.
  • Improved the persistent file-search index with a new schema and more reliable incremental upsert, subtree deletion, trigram maintenance, and duplicate/path handling on both macOS and Linux servers.
  • Updated the macOS and native Linux server implementations in parallel for the new HTTP administration, transfer API, Conference controls, Classic download fix, avatar compatibility, and search-index behavior.

New in 1.0.3

  • Improved account-group inheritance: existing accounts that still use their group's default permissions and nickname color now follow later group changes, while explicit per-account overrides remain preserved.
  • Added persistent per-account transfer statistics for download/upload counts and transferred bytes, exposed to modern administration clients on both macOS and native Linux servers.
  • Server-side directory symlinks can now intentionally open recursive shared directory trees and are presented to clients as normal folders. Nested share hops are limited to 32, while personal home directories remain strictly confined.
  • External file symlinks are not promoted to directory shares, preserving the distinction between explicitly shared directories and ordinary symbolic links.
  • Improved Classic agreement compatibility by normalizing modern line endings and supplying a real Classic text-style record so agreement text is displayed correctly by old clients.
  • Improved Unicode interoperability with Classic clients: emoji sent by modern users or the local Bot are converted for Legacy recipients to compact readable aliases such as *laughing*, while modern recipients continue to receive the original emoji.
  • Improved login/user-list robustness for modern clients by keeping large avatar payloads out of the packed login user list and synchronizing avatars, status messages, group colors, and transport markers through individual user updates.
  • News reaction changes are now broadcast to other connected modern clients so reaction counts and users can refresh immediately.
  • Improved dedicated account-group Files roots and their validation, including support for intentionally provisioned server-side directory shares while retaining strict path and personal-directory safety checks.
  • Updated the native Linux server in parallel with the macOS/Swift server, including group-inheritance persistence, transfer statistics, recursive directory-share handling, Classic agreement formatting, and Unicode-to-Classic emoji fallbacks.
  • Improved Classic Conference compatibility: join and leave notifications now follow the original protocol ordering, disconnected users are removed reliably from Classic Conference lists, and modern-only presence extensions are no longer sent to Legacy clients.
  • Improved Classic user-update and avatar compatibility by keeping modern status/color extensions and oversized modern avatar payloads away from Legacy update packets and using Classic-safe avatar data where appropriate.
  • Improved the persistent file-search index: an existing index is now reused after a server restart instead of being rebuilt every time, while full rebuilds can still be started manually.
  • Added a configurable automatic full search-index rebuild interval in hours. A value of 0 disables scheduled full rebuilds, and the interval is measured from the last successful full rebuild across server restarts.
  • Drop Boxes and everything below them are now excluded from the search index during both full rebuilds and incremental file updates.
  • Improved incremental search-index failure handling: the server falls back to filesystem search instead of unexpectedly starting a complete background rebuild.
  • Deleting files or folders inside server-side directory-symlink shares now works across filesystem boundaries while preserving the central Server Trash behavior.

New in 1.0.2

  • Added persistent Bot command rules with per-rule enable/disable state, configurable commands and responses, and {name} / {login} template expansion.
  • The local Bot can now respond inside the active Conference or directly by Private Message. Conference commands use #<command>, while direct messages to the Bot require no prefix.
  • The Bot automatically joins a target Conference when necessary, wakes before sending messages, and keeps normal Conference membership and permission semantics.
  • Added a full RSS 2.0 and Atom feed service for the local Bot, including multiple feeds, configurable target Conferences, polling intervals, summary lengths, and optional article images.
  • RSS state is persisted so existing articles are marked as seen during first initialization and are not reposted after a restart. Conditional HTTP requests use ETag and Last-Modified where available.
  • RSS article descriptions are cleaned and shortened before posting, common WordPress footer text is removed, and supported feed images are stored through the existing Carracho media system.
  • Added remote administration commands for saving Bot command rules, saving RSS feed configuration, and testing a feed. RSS tests post the fetched article into Public.
  • Hardened RSS fetching with HTTP/HTTPS validation, local and reserved network blocking, redirect checks, download limits, and timeouts.
  • Fixed the native Linux RSS test path that could reset the administrator connection during a feed test.
  • The native Linux server now uses libcurl and libxml2 for RSS/Atom support; Debian build instructions have been updated accordingly.

New in 1.0.1

  • Added a full native macOS application menu, including Sparkle-based Check for Updates support for Carracho Server.
  • Added optional menu bar operation with dedicated Light and Dark Mode icons, including the ability to hide the Dock icon and restore the server window directly from the menu bar.
  • Server and Tracker can now be started and stopped independently with separate controls, while the existing macOS system-service options remain available.
  • Improved menu bar responsiveness by removing synchronous system-service status checks from the menu-opening path.
  • Added support for separate modern and Classic/Legacy file roots. Modern sessions use the primary file root, while Classic clients can optionally be assigned a dedicated legacy file root.
  • Added the modern Post News account permission and improved News posting acknowledgements so clients receive an authenticated success or error result.
  • File label changes are now broadcast live to other connected modern clients, including users whose account or group exposes the same file through a different virtual path.
  • Permission changes for connected modern users are now pushed to their active sessions, allowing file and Dropbox access changes to take effect without reconnecting.
  • Added TCP keepalive handling to detect and remove connections from clients that disappear without a clean disconnect, while normal inactive users remain connected.
  • Improved Tracker status presentation and standardized primary server controls to the macOS system-blue appearance.
