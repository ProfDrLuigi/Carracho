New in 1.0.3

  • Improved account-group inheritance: existing accounts that still use their group's default permissions and nickname color now follow later group changes, while explicit per-account overrides remain preserved.
  • Added persistent per-account transfer statistics for download/upload counts and transferred bytes, exposed to modern administration clients on both macOS and native Linux servers.
  • Server-side directory symlinks can now intentionally open recursive shared directory trees and are presented to clients as normal folders. Nested share hops are limited to 32, while personal home directories remain strictly confined.
  • External file symlinks are not promoted to directory shares, preserving the distinction between explicitly shared directories and ordinary symbolic links.
  • Improved Classic agreement compatibility by normalizing modern line endings and supplying a real Classic text-style record so agreement text is displayed correctly by old clients.
  • Improved Unicode interoperability with Classic clients: emoji sent by modern users or the local Bot are converted for Legacy recipients to compact readable aliases such as *laughing*, while modern recipients continue to receive the original emoji.
  • Improved login/user-list robustness for modern clients by keeping large avatar payloads out of the packed login user list and synchronizing avatars, status messages, group colors, and transport markers through individual user updates.
  • News reaction changes are now broadcast to other connected modern clients so reaction counts and users can refresh immediately.
  • Improved dedicated account-group Files roots and their validation, including support for intentionally provisioned server-side directory shares while retaining strict path and personal-directory safety checks.
  • Updated the native Linux server in parallel with the macOS/Swift server, including group-inheritance persistence, transfer statistics, recursive directory-share handling, Classic agreement formatting, and Unicode-to-Classic emoji fallbacks.
  • Improved Classic Conference compatibility: join and leave notifications now follow the original protocol ordering, disconnected users are removed reliably from Classic Conference lists, and modern-only presence extensions are no longer sent to Legacy clients.
  • Improved Classic user-update and avatar compatibility by keeping modern status/color extensions and oversized modern avatar payloads away from Legacy update packets and using Classic-safe avatar data where appropriate.
  • Improved the persistent file-search index: an existing index is now reused after a server restart instead of being rebuilt every time, while full rebuilds can still be started manually.
  • Added a configurable automatic full search-index rebuild interval in hours. A value of 0 disables scheduled full rebuilds, and the interval is measured from the last successful full rebuild across server restarts.
  • Drop Boxes and everything below them are now excluded from the search index during both full rebuilds and incremental file updates.
  • Improved incremental search-index failure handling: the server falls back to filesystem search instead of unexpectedly starting a complete background rebuild.
  • Deleting files or folders inside server-side directory-symlink shares now works across filesystem boundaries while preserving the central Server Trash behavior.

New in 1.0.2

  • Added persistent Bot command rules with per-rule enable/disable state, configurable commands and responses, and {name} / {login} template expansion.
  • The local Bot can now respond inside the active Conference or directly by Private Message. Conference commands use #<command>, while direct messages to the Bot require no prefix.
  • The Bot automatically joins a target Conference when necessary, wakes before sending messages, and keeps normal Conference membership and permission semantics.
  • Added a full RSS 2.0 and Atom feed service for the local Bot, including multiple feeds, configurable target Conferences, polling intervals, summary lengths, and optional article images.
  • RSS state is persisted so existing articles are marked as seen during first initialization and are not reposted after a restart. Conditional HTTP requests use ETag and Last-Modified where available.
  • RSS article descriptions are cleaned and shortened before posting, common WordPress footer text is removed, and supported feed images are stored through the existing Carracho media system.
  • Added remote administration commands for saving Bot command rules, saving RSS feed configuration, and testing a feed. RSS tests post the fetched article into Public.
  • Hardened RSS fetching with HTTP/HTTPS validation, local and reserved network blocking, redirect checks, download limits, and timeouts.
  • Fixed the native Linux RSS test path that could reset the administrator connection during a feed test.
  • The native Linux server now uses libcurl and libxml2 for RSS/Atom support; Debian build instructions have been updated accordingly.

New in 1.0.1

  • Added a full native macOS application menu, including Sparkle-based Check for Updates support for Carracho Server.
  • Added optional menu bar operation with dedicated Light and Dark Mode icons, including the ability to hide the Dock icon and restore the server window directly from the menu bar.
  • Server and Tracker can now be started and stopped independently with separate controls, while the existing macOS system-service options remain available.
  • Improved menu bar responsiveness by removing synchronous system-service status checks from the menu-opening path.
  • Added support for separate modern and Classic/Legacy file roots. Modern sessions use the primary file root, while Classic clients can optionally be assigned a dedicated legacy file root.
  • Added the modern Post News account permission and improved News posting acknowledgements so clients receive an authenticated success or error result.
  • File label changes are now broadcast live to other connected modern clients, including users whose account or group exposes the same file through a different virtual path.
  • Permission changes for connected modern users are now pushed to their active sessions, allowing file and Dropbox access changes to take effect without reconnecting.
  • Added TCP keepalive handling to detect and remove connections from clients that disappear without a clean disconnect, while normal inactive users remain connected.
  • Improved Tracker status presentation and standardized primary server controls to the macOS system-blue appearance.
