New in 1.1.4

  • Updated the macOS client to version 1.1.4 (build 15).
  • Stable Message Center conversation identity — Private conversations in Message Center no longer use the server's transient numeric userID as their durable identity. Modern servers now provide the authenticated account UUID for each visible user, and Carracho stores and selects conversations by that stable account identity while keeping the numeric user ID only as the current live routing address.
  • Private-message history survives app restarts — When the stable account UUID arrives after a conversation has already collected messages in the current session, Carracho now persists the complete promoted conversation history instead of only its conversation metadata. This fixes private-message history disappearing after restarting the app in that race window.
  • Boot-scoped fallback when a peer UUID is unavailable — If a server does not provide a stable peer account UUID, including original/Classic servers and older modern Carracho builds, Carracho keeps that Private Message history in a separate local store keyed by the current server boot and numeric user ID. The boot namespace is resolved from server uptime: restarting only Carracho restores the same history, while restarting the server creates a new namespace so a recycled numeric user ID cannot inherit another user's messages.
  • Background bookmark Message Center persistence — Private Messages received while another bookmark remains connected in the background are now applied directly to that bookmark's Message Center snapshot and persisted immediately. Message edits and reactions are persisted there as well. Quitting Carracho no longer loses those events merely because the bookmark had not been activated again first.
  • Safer local private-message history — Message Center now stores durable Private Message conversations in a v2 SQLite schema keyed by stable peer account UUID. Older session-ID-based private-message history is deliberately not imported automatically because its account ownership cannot be proven safely after IDs have been recycled; those old rows are left untouched in the local database but ignored by the new history. Message edits, reactions, drafts, unread state, avatars, transport metadata and the existing 500-message per-conversation limit continue to use the same Message Center behavior.
  • Safe fallback for older servers — If a server does not provide a stable peer UUID, Carracho persists the numeric-ID conversation only after it has identified the current server boot from server uptime. This applies to original/Classic servers as well as older modern Carracho servers that predate stable peer-identity metadata. The history is safe across client reconnects and app restarts, but it is not rebound after a server restart.
  • Optional disconnect confirmation — A new Confirm disconnection option is available under Carracho Settings → General → App Behavior. When enabled, manually disconnecting from an active server requires confirmation before the connection is closed. Cancelling a pending automatic reconnect and internal protocol-driven disconnects remain immediate and do not show the confirmation dialog.

New in 1.1.3

  • Updated the macOS client to version 1.1.3 (build 14).
  • Files now supports deleting multiple selected server items in one batch. Folder/child selections are normalized to avoid redundant deletes, successful items disappear from the visible tree immediately, and individual failures are reported without cancelling successful deletions.
  • The Files Upload dialog now allows selecting multiple local files and folders at once. All selected items are added to the existing transfer queue together, and multi-item Finder drag-and-drop uses the same batched enqueue path.
  • Added an App Behavior setting controlling whether closing the last window with the red macOS close button quits Carracho or leaves it running in the Dock. Clicking the Dock icon restores the main window when the app remains active.

New in 1.1.2

  • Updated the macOS client to version 1.1.2 (build 13).
  • Added reactions to modern Private Messages in Message Center. A ☺ React action offers the same reactions as News, and each participant can set, replace, or remove one reaction per message.
  • Reaction state is persisted locally with Message Center history. Reaction-capable modern Private Messages use a shared message UUID, including messages with media attachments, while existing five-minute edit restrictions remain unchanged.
  • Guest accounts no longer see Send Offline Messages. If an account becomes Guest while connected, an open offline-message composer is closed; the server also enforces the restriction.
  • Removed the visible server address/IP column from Tracker result tables. The endpoint remains available internally when connecting to the selected server.
  • Unread Conference messages, Private Messages, and Offline Messages now use compact red badges with white counts in the sidebar, matching bookmark notification badges. Expanded Conferences show the badge on the affected room; when collapsed, the total moves to the Conferences row.
  • Added a General setting under Server Messages to hide user sign-in/sign-out notifications when people enter or leave a server. Presence tracking, the user list, and configured event sounds remain active.

New in 1.1.1

  • Updated the macOS client to version 1.1.1 (build 12).
  • Added a third server-header line showing Legacy Mode = On or Legacy Mode = Off, so modern users can immediately see whether the connected server allows Classic/Legacy clients.
  • The Legacy Mode value comes from the server's actual compatibility configuration rather than being inferred from currently connected users. Older modern servers that do not advertise the capability simply omit the line.
  • Changing the server authentication mode from Advanced Administration now updates the displayed Legacy Mode state immediately after the setting is saved.
  • Classic/Legacy users now show @ Legacy in the status row of the modern user list, making historical-client connections easy to identify without changing normal modern user status messages.
  • Fixed Modern Only login. The modern client now authenticates using a verifier-based PBKDF2-SHA256/HMAC challenge-response flow and no longer depends on the retained Legacy credential.

New in 1.1.0

  • Updated the macOS client to version 1.1.0 (build 11).
  • Added optional Guest Upload Approval in Advanced Administration. When enabled, completed Guest uploads remain hidden until an Administrator approves or rejects them; the pending queue shows destination, uploader, size, and upload time.
  • Added Approve, Reject, and Refresh controls for pending Guest uploads. Account Holder and Administrator uploads continue to publish immediately.
  • Connected Administrator bookmarks now show 🚨 whenever that server has pending Guest uploads awaiting approval. The alert updates live for background-connected bookmarks and disappears after the final pending item is approved or rejected.
  • Modern Guest uploaders now receive a clear notice after the server has fully accepted a moderated upload into the approval queue, explaining that the item will become visible only after Administrator approval.
  • Folder uploads are handled as one complete moderated transfer: the awaiting-approval notice is sent only once, after the entire folder tree and all contained file data have been received and verified.
  • Older modern servers that do not support Guest Upload Approval leave the new controls unavailable without affecting the rest of Administration.

New in 1.0.9

  • Updated the macOS client to version 1.0.9 (build 10).
  • Greatly improved scrolling performance for large server-wide Files search results. Search rows now use lightweight reusable cells, stable result snapshots, cached size/date/kind text, and cached file-type artwork instead of repeating expensive layout, sorting, and LaunchServices work while scrolling.
  • Improved very large file-search transfers by yielding between already-buffered records and keepalive frames, preventing deep callback recursion and making long result streams more robust.
  • Conference history now keeps a sender snapshot with each received message, so a user's nickname, avatar, and group color remain visible after that user disconnects instead of falling back to an unknown/default presentation.
  • Refined Tracker presentation by using the dedicated Carracho Tracker artwork for saved Tracker rows.
  • Added an Advanced server setting for Bot File Watchers that controls whether Guest accounts receive watcher announcements. Account Holders and Administrators continue to receive them by default; older modern servers that do not support the new setting keep the control disabled without breaking the rest of Administration.

New in 1.0.8

  • Updated the macOS client to version 1.0.8 (build 9).
  • Added message editing for modern Carracho servers. Your own Conference and Private Messages can be edited for up to five minutes after sending; edited messages are marked accordingly and Private Message edit state is preserved in the local Message Center history.
